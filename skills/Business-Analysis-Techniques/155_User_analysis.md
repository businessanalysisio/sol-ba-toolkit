# User analysis

## Overview

Identifies every group that will use the proposed solution and profiles each group's characteristics so requirements reflect real users rather than an imagined average one. A user group profile typically records: the role and its goals when using the system, frequency of use (daily heavy users versus occasional ones), IT literacy and domain expertise, physical working environment (office desk, warehouse floor, customer-facing counter, mobile), accessibility needs, geographic distribution, and volumes. The differences drive different requirements — a call-centre agent using the system 200 times a day needs keyboard shortcuts and speed; a citizen using it once a year needs guidance and forgiveness.

## Context & Usage

Carried out early in requirements definition, feeding usability and non-functional requirements, interface design, training-needs analysis and rollout planning. It also protects against a classic elicitation bias: the users who attend workshops are rarely representative of the whole population, so the profiles show who is missing from the conversation. Findings are often compressed into personas — named, humanised archetypes of each group — which keep design discussions anchored to "would Priya the night-shift supervisor cope with this?" rather than abstract debate.
