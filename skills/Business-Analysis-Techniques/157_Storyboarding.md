# Storyboarding

## Overview

Borrowed from film-making: a user journey is drawn as a sequence of frames, each frame a rough sketch of what the user sees or does at that point — the screen displayed, the document handled, the decision faced — with annotations explaining the action and what triggers the move to the next frame. The frame-by-frame format makes flow the object of scrutiny: unlike a single screen design, a storyboard exposes ordering problems, missing steps, dead ends and moments where the user lacks the information the next step assumes. Deliberately low fidelity (pencil boxes and stick figures) keeps feedback focused on the journey rather than fonts and colours.

## Context & Usage

Used when elaborating scenarios and user stories into interaction designs, and when validating a proposed process with the people who will live it — stakeholders point at a frame and say "that's not what happens next", which is precisely the correction wanted. Storyboards precede wireframing and prototyping in the fidelity ladder: cheapest first, so the expensive artifacts are built only for journeys already agreed. They work especially well for cross-channel journeys (phone, web, branch, back office) that no single screen mock-up can represent.
