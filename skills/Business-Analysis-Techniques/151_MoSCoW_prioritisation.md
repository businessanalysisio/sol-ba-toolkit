# MoSCoW prioritisation

## Overview

A four-level priority scheme originating in DSDM, whose name spells out the categories (the lowercase o's exist only for pronunciation): Must have — non-negotiable; without it the solution is unworkable, unlawful or unsafe, so failure to deliver means the delivery has failed; Should have — important and painful to omit, but a workaround exists for a while; Could have — desirable and delivered if capacity allows, the first candidates to drop under pressure; Won't have this time — explicitly out of scope for this increment, recorded so the expectation is managed rather than forgotten. DSDM guidance keeps Must-have effort to no more than about 60% of a timebox, so the Should and Could categories provide the contingency that protects the guaranteed core.

## Context & Usage

Applied when requirements or backlog items must be ranked against a fixed deadline or budget — the flex is in scope, so priorities decide what flexes. The categories only work if policed: the test for a Must is "what happens if we ship without it?", and an answer short of "we can't ship" demotes it. Priorities are agreed with stakeholders (not assigned by the BA), revisited at every increment, and a set that is 80% Musts signals the negotiation has not really happened yet.
