# Task Analysis / Task modelling

## Overview

Decomposes the human work inside a process step into the discrete tasks a person actually performs, then breaks each task into its component steps, the objects handled, and the skills and knowledge required. The classic form is Hierarchical Task Analysis (HTA): an overall goal at the top, sub-tasks beneath it, and "plans" that state the order and conditions under which the sub-tasks are carried out (e.g. "do 1, then 2; repeat 3 until the queue is empty"). Beyond structure, the analyst records attributes such as task frequency, duration, complexity, error consequences and the working environment, which a process-level model deliberately hides.

## Context & Usage

Reach for task analysis when a single box on a swimlane diagram — "assess application", "handle claim" — conceals substantial user work that the solution must support. It sits between business process modelling and detailed solution design: outputs drive user interface design, usability and performance requirements, training-needs analysis, job design and workload estimation. Data is gathered by observing and interviewing the people doing the work; a common trap is modelling the procedure manual rather than what performers really do, so validate the model against live observation.
