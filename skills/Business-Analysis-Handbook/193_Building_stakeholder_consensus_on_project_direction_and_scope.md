# Building stakeholder consensus on project direction and scope

## Overview

Consensus is engineered, not hoped for. Start by surfacing disagreement deliberately — one-to-one pre-meetings with each key stakeholder to learn their position, red lines, and what they think the project is for, so the group session holds no ambushes. In the room, work from visible shared artifacts: a context diagram, an explicit in-scope/out-of-scope list, a draft objective statement — people converge faster on a thing they can point at than on abstract discussion. Use facilitated prioritisation to force trade-offs instead of letting everyone's item be "essential". Record the agreed scope in writing, name what was explicitly excluded and why, and obtain visible sign-off so later "I never agreed to that" has a documented answer. Where two stakeholders genuinely cannot be reconciled, frame the disagreement crisply and escalate to the sponsor for a decision rather than papering over it.

## Context & Usage

Critical at project start, when the direction is set, and again at every major replan or descoping exercise. The warning signs that consensus is missing rather than merely unspoken: recurring re-litigation of settled decisions, stakeholders briefing against the project privately, and requirements that contradict each other along departmental lines. A false consensus — silence in the meeting, resistance afterwards — is worse than an open dispute, because it fails later and less visibly.
