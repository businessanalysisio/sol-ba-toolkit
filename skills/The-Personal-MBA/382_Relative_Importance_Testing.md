# Relative Importance Testing

## Overview

If you ask customers how important each feature is, they rate everything as important — which tells you nothing. Relative importance testing solves this by forcing trade-offs: instead of rating attributes independently, respondents must choose between bundles, rank options, or say which of two things they would give up. Because every choice sacrifices something, their selections reveal true priorities rather than polite wish-lists. This is the logic behind conjoint analysis, and Kaufman presents it as the reliable way to learn which economic values and features actually drive buying decisions. The method converts vague enthusiasm ("I want it all") into an ordered ranking you can design and price against.

## Context & Usage

Use relative importance testing when deciding which features to build first or which attributes to emphasize, and you suspect stated preferences are inflated. Rather than asking "Do you want faster delivery?" (everyone says yes), present realistic packages — cheaper-but-slower versus pricier-but-faster — and see which people actually pick. A car company learning that buyers will trade trunk space for better fuel economy, but not for a lower price, gains a concrete design directive that a feature-importance survey would have buried. The output feeds directly into trade-off and pricing decisions.
