# Value Modelling

## Overview

Focuses solution development on value delivery by tracing decisions back to the value perspective of the stakeholder. In the POA reading, value modelling defines the product as a combination of customer and stakeholder value, letting the team trace every product decision — such as the inclusion or exclusion of a feature — to customer value derived or deferred. The Guide's diagnosis is that many poorly defined, misaligned products are described merely as a set of features or solution components with the derivable value ignored; it names a family of remedies — the value proposition canvas, the value model, mean value charts, and customer value flowcharts — each aligning the product to stakeholder goals and exposing gaps between expected and perceived value from different stakeholder perspectives.

## Context & Usage

Build each value model with a specific stakeholder or customer segment in mind, and include that stakeholder in the discussion — the model collates the full spectrum of value that stakeholder derives, which aids discovery and creates an emotional connection. As a visual construct it communicates the nature of value being delivered far better than a feature list, but it must be refreshed whenever customer needs evolve through changing expectations, new ways to achieve outcomes, novel ideas, or additional features; value-based metrics then track how customer perception shifts and what needs to change. The whole point, per the Guide, is converting the team from a solution-based outlook to a value-focused one, so products are envisioned top-down with each PBI, story, and feature tracing back to the envisioned value of the product.
