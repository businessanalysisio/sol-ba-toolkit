# Minimal Viable Product

## Overview

The smallest set of features needed to deliver value to stakeholders and satisfy early adopters in the shortest possible time — used to avoid the cost and risk of building the wrong product by testing a hypothesis, reducing waste, and accelerating feedback. The Guide is precise about boundaries: an MVP is a viable working product built on evidence-based learning from customers' direct experience; it might be a functional prototype or even a shippable product; but it is not all the must-have features, not a Proof of Concept (POCs are internal and validate technical feasibility), and not a single fixed release. Defining one takes four components: target audience, a goal or hypothesis to test, the minimal defined requirements, and a mechanism to measure learning.

## Context & Usage

Applied to product development, services (commonly testing willingness to pay), feature development (gauging demand), and market-test differentiation. The Guide's five-step process: analyze the MVP's purpose (desirability vs. usability; new vs. existing product); select the MVP type by business context (from an ad leading to an information page, to a wireframe, to a functioning product); identify the minimum feature set from journey-mapping sessions, separating must-haves from nice-to-haves; build the roadmap from MVP to minimum marketable feature (MMF) to minimum marketable product (MMP); and measure validated learning each release. Key caution: "cheap and fast" must not be the goal, budget constraints should not drive the definition, and it is not useful for a clear or simple solution.
