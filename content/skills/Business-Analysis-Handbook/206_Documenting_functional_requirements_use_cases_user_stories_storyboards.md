# Documenting functional requirements (use cases, user stories, storyboards)

## Overview

Documenting functional requirements (use cases, user stories, storyboards) is a business analysis practice for handling requirements and product definition. It helps the BA move from ambiguous stakeholder input to structured analysis, documented decisions, and actionable outputs.

## Context & Usage

Use this when documenting functional requirements is creating uncertainty, disagreement, or missing detail. The BA should clarify purpose, collect evidence, involve the right stakeholders, and convert the result into a documented artifact or decision.
