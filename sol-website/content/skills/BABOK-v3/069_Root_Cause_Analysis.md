# Root Cause Analysis

## Overview

Finding the fundamental cause of a problem rather than treating symptoms. Root Cause Analysis uses techniques like 5 Whys (iteratively asking 'why' until the root cause emerges) and Fishbone/Ishikawa diagrams (categorizing potential causes by type).

## Context & Usage

Applied during Strategy Analysis (analysing current state problems) and RADD (ensuring requirements address real needs). The 5 Whys approach: state the problem → ask 'Why?' → repeat until the root cause is found (usually 3-7 iterations). Fishbone diagrams organize causes into categories: People, Process, Technology, Environment, Materials, Management. Always validate the identified root cause before designing solutions.
